# pdf-shrink

Windows向けのPDF一括軽量化CLIです。入力フォルダーを再帰的に走査し、
PDFの特性に応じてPyMuPDFまたはqpdfで圧縮候補を作成します。候補を検証し、
既定の削減条件を満たす場合だけ採用します。採用しない場合や処理を安全に
継続できない場合は、原本を出力フォルダーへコピーしてミラー構造を維持します。

## 必要環境

- Windows
- Python 3.13以上
- [uv](https://docs.astral.sh/uv/)

Python依存関係は `uv sync` で導入します。qpdfはPATH、指定パス、ローカル
キャッシュの順に探索し、見つからない場合はバージョン12.3.2のWindows向け
配布ZIPをGitHub Releasesから取得します。

## 実行

```powershell
uv sync
uv run pdf-shrink run --input C:\PDF
```

出力先の既定値は `<入力フォルダー>_軽量化` です。入力と出力に同じフォルダー、
または親子関係にあるフォルダーは指定できません。

主なオプションは次のとおりです。

```text
--output PATH       出力フォルダー
--workers N         並列プロセス数。既定値は2
--dry-run           出力PDFを作らず、判定結果だけを記録
--safe              非可逆画像縮小を無効化
--limit N           サイズ上位N/2件と固定seedのランダムN/2件を処理
--retry-errors      復旧コピー済みの前回ERRORを再処理
--qpdf-path PATH    qpdf.exeを明示指定
```

`--dry-run` でも状態DBと `report.dry-run.csv` は書き込みます。出力PDFと一時PDFは
作成しません。通常実行のレポートは `report.csv` です。状態DBは出力フォルダーの
親にある `.pdf-shrink/state.sqlite3` へ保存します。

## 処理方針

- 256 KiB未満のPDFは圧縮せず、通常実行では原本をコピーします。
- 暗号化、電子署名、フォーム、添付ファイル、修復済みPDFなどは圧縮対象外です。
- 画像がページ面積の80%以上で、可視テキストが20文字以下のページを
  スキャンページと判定します。全ページの80%以上が該当すると非可逆圧縮候補を
  作成します。`--safe` では常に可逆圧縮候補を作成します。
- 候補はqpdf構造検査、ページ数、NFC正規化後の抽出テキスト、72 DPIの
  グレースケール表示差分で検証します。
- 可逆候補は64 KiBかつ2%以上、非可逆候補は256 KiBかつ5%以上削減できる場合に
  採用します。
- 出力は同じディレクトリの一時ファイルへコピーしてから `os.replace` で公開し、
  既存の正常な出力を途中書き込みで破損させないようにします。

代表的なstatusは次のとおりです。

| status | 意味 |
| --- | --- |
| `ADOPTED_LOSSLESS` | 可逆圧縮候補を採用 |
| `ADOPTED_LOSSY` | 非可逆圧縮候補を採用 |
| `UNCHANGED` | 候補の削減量が不足したため原本を採用 |
| `SKIPPED_*` | 小容量または安全上の理由で圧縮せず原本を採用 |
| `DRY_RUN_LOSSLESS` | dry-runで可逆圧縮予定と判定 |
| `DRY_RUN_LOSSY` | dry-runで非可逆圧縮予定と判定 |
| `ERROR` | 処理に失敗。可能なら原本を復旧コピー |

現在の入力に `ERROR` が1件以上あればCLIは終了コード1、それ以外は0を返します。
入力・出力指定またはqpdf準備の失敗も1、不正な数値オプションは2です。

## 設計境界

| モジュール | 責務 |
| --- | --- |
| `cli.py` | 引数解析、ログ設定、終了コードへの受け渡し |
| `runner.py` | 一括処理の順序、ProcessPool、状態保存、レポート対象の決定 |
| `models.py` | 入力スナップショット、検査結果、処理結果、status |
| `config.py` | 型付き設定と再開条件ハッシュ |
| `discovery.py` | 入力検証、PDF探索、パイロット選択、SHA-256取得 |
| `worker.py` | 1ファイルの検査、候補生成、検証、採否判断 |
| `inspect_pdf.py` | PDFの安全性検査とスキャン主体判定 |
| `transform.py` | 可逆・非可逆の圧縮候補生成 |
| `validate.py` | 元PDFと候補の構造・内容比較 |
| `output.py` | 原本または検証済み候補の原子的な公開 |
| `state.py` | SQLite永続化と再開判定 |
| `report.py` | CSVとコンソールサマリー |
| `qpdf.py` | qpdfの探索、取得、実行 |

workerは `ProcessResult` を返し、CLIやrunnerからworker内部の変換実装へは
アクセスしません。状態DBには処理対象を決めた時点の入力SHA-256を保存します。
処理中に入力が変わった場合、新しい内容を誤って処理済みと記録せず、次回実行で
再処理します。レポートは状態DB全体ではなく、現在選択した入力だけを対象にします。

## 開発と検証

```powershell
uv sync --dev
uv run pytest -q
uv run python -m compileall -q src tests
uv run python -m pdf_shrink --help
```

テストにはqpdfの実行を含む統合テストがあります。初回はqpdfの取得が発生する
可能性があります。

## 優先して残す改善課題

1. qpdf配布ZIPの真正性

   ダウンロードするバージョンと展開先パスは固定・検査していますが、配布ZIPの
   SHA-256または署名は検証していません。自動取得を配布方式として維持するなら、
   公式に管理されたハッシュの固定と更新手順が必要です。

2. 表示検証の局所的な差分

   現在の表示検証は全ページの72 DPIグレースケール画素について平均絶対差を計算し、
   5%以下を許容します。小領域だけの欠落はページ全体の平均で薄まる可能性があります。
   実PDFコーパスを用意したうえで、ページ単位の上限や局所差分を追加する必要があります。

3. 入力ファイルの同時更新

   処理前スナップショットにより次回実行で変更を検出できますが、処理中の入力を
   ロックしてはいません。別プロセスが同時にPDFを更新する運用では、安定した
   ステージング領域へ入力をコピーしてから処理する方式を検討してください。

4. 実データでの判定閾値

   現在のテストは合成PDFが中心です。スキャン判定、削減率、表示差分の既定値を
   変更する前に、代表的な実PDFと失敗例を匿名化した回帰コーパスが必要です。
