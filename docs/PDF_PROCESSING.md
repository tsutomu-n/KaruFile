# PDF処理の流れと判断基準

**フォント置換の実行には対象の明示指定が必要です。置換先の字体はメイリオが既定なので、字体名の指定は不要です。通常のPDF圧縮ではフォントを変更しません。**

KaruFileは、PDFを一冊単位で保護判定し、処理を許可できた文書だけに圧縮候補を作ります。
文字なし・画像と切り抜きだけのスキャンPDFは、既定で300 DPI・グレー・JPEG品質92に圧縮します。
文字・画像混在や描画線を含む未指定PDFなどは原本を別の出力先へコピーします。
文章向けでは、検証に合格して原本より小さくなった候補のうち、最小のものを採用します。
この方針は`standard`と`compact`で共通です。

この文書は現行処理を順に理解するための説明です。実行手順・コマンド例は
[利用者マニュアル](../MANUAL.md#pdfの保護と文章向けの指定)、正確なオプション・数値・記録形式は
[技術リファレンス](REFERENCE.md#pdf処理)を参照してください。

PDF1冊も直接入力できます。単一PDFの保存先と自動画像化の上限・比較基準は
[技術リファレンス](REFERENCE.md#自動スキャン画像化と単一pdf入力)を参照してください。

## 1. 入力を調べ、指定と保存先を確認する

統合CLIの`karufile.py`から、PDF専用の`pdf-shrink`を実行します。入力フォルダー内のPDFを
再帰的に探し、相対フォルダー構造を保って別の出力先へ保存します。PDF内の画像もPDF側で処理します。

入力と出力が同じ場所、互いに親子の場所、危険なリンク先の場合は処理を拒否します。
入力のサイズ・SHA-256等を記録し、処理中の変化も確認します。入力自体は変更・削除しませんが、
ロックはしないため、実行中に別のアプリケーションで原本を書き換えないでください。

保護・許可パターンは入力からの相対パスに照合します。大文字小文字を区別せず、`/`と`\`は
同じ区切りとして扱います。`*`はフォルダー区切りにも一致するため、`*.pdf`は全PDFを選びます。
各指定は反復でき、空のパターン、絶対パス、`..`要素を含むパスは使えません。

最初に保護指定を適用します。それ以外で同じPDFが文章・文章スキャン・白黒書類スキャン・写真・字体統一の複数の許可に
一致すると、候補生成や完成出力の公開前にエラーにします。

## 2. PDF全体を保護するか判定する

| 入力・指定 | 判定と処理 |
|---|---|
| `--pdf-preserve-pattern`に一致 | 他の許可より優先して原本コピー |
| 無指定で、文字があり、画像・描画パス・その他の非文字描画がない | 文章向け候補を生成。空白ページの混在は許可 |
| 無指定で、文字データなし・画像とclipのみ（空白混在可） | ページ全体を300 DPI・グレー・JPEG品質92へ。写真だけのPDFも含む |
| 無指定で、文字・画像混在や描画線などを含む | 一冊まるごと原本コピー |
| `--pdf-text-pattern`に一致 | 文章と水平・垂直の直線・枠線だけを許可。画像、曲線、塗り、斜線などがあれば一冊まるごと保護 |
| `--pdf-text-scan-pattern`に一致 | 単純なRGB／Gray画像で構成された文章スキャンを許可。マスク、特殊な色空間・Decode、inline画像、曖昧な配置などがあれば一冊まるごと保護 |
| `--pdf-text-scan-bilevel-pattern`に一致 | 同じ構造検査を行い、白黒2色の候補を追加。色・灰色の階調が不要な書類だけ明示指定 |
| `--pdf-font-replace-pattern`に一致 | 日本語・英語をWindowsのメイリオRegularへ統一する候補を許可。欠字や未対応の符号化・PDF構造は一冊まるごと保護 |
| `--pdf-photo-pattern`に一致 | 写真向け処理を許可。文書内の加工条件を満たすJPEGだけを縮小し、対象外画像は保持 |

暗号化・署名・フォーム・添付・修復済みPDFなどの共通除外も適用します。文章向けでは、
レイヤーや注釈など対応範囲外の構造、上限超過も保護理由になります。空白ページだけのPDFは
文字を確認できないため保護します。検査処理そのものの失敗は`ERROR`として扱います。

文章・表・写真という内容の意味を自動認識する機能ではありません。特にスキャンと写真は、
利用者が内容を確認して許可します。表の指定も構造上の検査を追加するもので、表の意味を理解するものではありません。

保護対象ではqpdf最適化、JPEG可逆最適化、縮小、比較用の追加候補を生成しません。
コピー後のSHA-256が原本と一致することを確認し、`PRESERVED_ORIGINAL`を記録します。
通常実行では事前のツール準備があるため、「保護対象だけならqpdfが不要」という意味ではありません。

PDF個別CLIでは、統合CLIの`--pdf-text-pattern`を`--text-pattern`とするように、名前の`pdf-`を外します。

## 3. 原本から候補を独立に作る

| 処理区分 | 比較する候補 |
|---|---|
| 文章・罫線表 | qpdf単独／使用文字のフォントサブセット化・整理圧縮＋qpdf／グレースケール化＋同じ整理圧縮＋qpdf |
| 自動スキャン | qpdf単独／全ページ300 DPI・グレー・JPEG品質92。独立検証し最小を採用 |
| 文章スキャン（明示指定） | qpdf単独／300 DPI目標のグレースケールJPEG品質92・85・80を、それぞれ整理圧縮＋qpdf |
| 白黒書類スキャン | 文章スキャンの候補に、300 DPI上限の1-bitグレー・Flate圧縮＋qpdfを追加 |
| 字体統一 | qpdf単独／WindowsのメイリオRegularへ置換・必要な文字をサブセット埋め込み＋qpdf |
| 写真 | 許可したJPEGを指定DPIへ縮小する候補とqpdf単独候補。任意指定でJPEG可逆候補も追加 |

各候補は原本から作ります。前の非可逆候補をさらに圧縮することはありません。
通常の文章候補はページを画像化せず、文字を再配置したり代替フォントへ置換したりしません。
字体統一は明示したPDFだけの別処理です。Windowsにある`Meiryo Regular`（既定）または`--pdf-font-family yu-gothic`で`Yu Gothic Regular`を使い、フォント自体の
字形・文字幅を加工せず、PDF側で字間を調整します。画像に焼き込まれた文字は置換できません。
文章スキャンに既存OCR文字層があれば保持します。新しいOCRは実行しません。
白黒書類候補はグレー画素値220未満を黒、220以上を白にします。文字認識や字形置換は行いません。
色・階調・薄い筆画への影響があるため、無指定へ適用せず、細字や印影を完成後に比較します。

文章スキャンの300 DPIはPDF上の配置サイズから求めます。同じ画像が複数箇所に置かれている場合、
全配置の最小実効DPIをX・Y軸ごとに使い、300 DPIを超える軸だけ縮小します。
元から300 DPI以下の軸は拡大しません。ただし、低DPI画像も同じ寸法でグレーJPEG候補になります。

写真は既定200 DPI、指定可能範囲150〜300 DPI、JPEG品質80です。単純な8-bit DeviceRGB／DeviceGrayの
DCT JPEGだけが縮小対象で、どちらの軸も縮まない画像は写真候補では再圧縮しません。
これは低DPIでもグレーJPEG候補を作る文章スキャンとの違いです。

PDF個別CLIの`--safe`では、文章のグレー候補を作らず、可逆候補だけを比較します。
文章スキャン指定・写真指定・字体統一指定・`--preset compact`との併用は引数エラーです。
`--lossless-jpeg`は通常の非可逆候補を無効化する指定ではなく、現行の保護方針では
保護されていない写真PDFにだけ追加候補を作ります。

## 4. 内容と表示を検証し、採用候補を選ぶ

文章向けでは、qpdf検査に加え、ページ数・形状、抽出文字とその位置、罫線・画像の配置、
リンク・しおり・メタデータを照合します。表示検査は候補の種類によって異なります。

| 候補 | 表示検査 |
|---|---|
| 文章向けの色を維持する候補（文章スキャンのqpdf単独も含む） | 全ページの72／300 DPI RGB描画が原本と完全一致 |
| グレー化した文章・罫線表 | 全ページの72／300 DPIグレー描画が原本のグレー描画と完全一致 |
| 文章スキャンのJPEG・二値化候補 | 原本のグレー描画と72 DPI全ページ・300 DPI画像配置領域を比較。全体平均差5%以下、最大32×32 pixelの局所平均差20%以下 |
| 写真の縮小候補 | 72 DPI RGB全ページと300 DPI RGB変更配置領域を比較。全体平均差5%以下、局所平均差20%以下 |
| 字体統一 | 表示文字・順序・位置、図表・画像等の保持を独立検証。字形の変化を許可し、コピー・検索時の推定空白差を別途記録 |

文章向けの上限は文書100ページ、画像80 MP、圧縮ストリーム64 MiB、候補検証の累積600 MPです。
検証画素数は原本・候補の両方を計上します。文書工程には300秒の協調的な時間上限があり、
処理の合間に確認します。個々のツール呼出しをちょうど300秒で強制停止する保証ではありません。
事前に分かる超過は原本保護、候補処理中の予算超過はその候補の棄却になります。
字体統一は通常文章とは別の構造・描画検証と予算を使います。正確な対応境界と数値は
[Windowsフォントへの明示置換](REFERENCE.md#windowsフォントへの明示置換)を参照してください。

文章・罫線表・文章スキャンでは、小容量PDFも処理し、検証済み候補が原本より小さい場合だけ採用します。
候補同士が同サイズならqpdf、色を維持したサブセット、グレーの順で優先し、スキャンJPEG同士なら
品質92、85、80、二値化の順です。原本と同サイズなら採用しません。
字体統一も原本より小さい最小の合格候補だけを採用し、qpdf単独との同サイズではqpdfを優先します。
このprofileではJPEG可逆の追加指定があっても候補を増やしません。

写真では256 KiB未満を除外し、可逆候補は16 KiBかつ2%、非可逆候補は64 KiBかつ5%以上の削減が必要です。
いずれも条件を満たす最小候補を選びます。「最小」はこの候補群と検証条件の範囲内を意味し、
小さくするために画質基準を緩めたり、別方式へ自動的に切り替えたりしません。

グレー化・二値化・JPEG再圧縮・字体置換は非可逆です。小さくならない、または全候補が検証不合格の場合は原本を残します。
ツール・破損・I/O障害の場合は原本復旧を試み、復旧できても`ERROR`を維持し、他のPDFを続行します。

## 5. 出力し、判断の理由を記録する

完成ファイルは検証した一時ファイルから公開します。代表的なstatusは次のとおりです。

| status | 意味 |
|---|---|
| `PRESERVED_ORIGINAL` | 保護判定で候補を生成せず原本コピー |
| `ADOPTED_LOSSLESS` | 検証済みの可逆候補を採用 |
| `ADOPTED_LOSSY` | 検証済みのグレー・スキャンJPEG・二値化・写真縮小・字体置換候補を採用 |
| `UNCHANGED` | 候補を試したが採用条件を満たさず原本コピー |
| `SKIPPED_SMALL` | 写真向けで256 KiB未満のため処理を省略 |
| `ERROR` | 処理失敗。復旧コピーの成功とは区別 |

PDFのCSVは出力先の親フォルダーの`report.csv`、状態DBは`.pdf-shrink/state.sqlite3`に保存します。
要求ポリシー、判定区分、許可根拠、保護理由は、それぞれ`requested_policy`、`classification`、
`permission_basis`、`preservation_reason`で確認できます。

`candidate_size`などの一次候補列は最初の候補の診断です。完成出力の大きさは`output_size`、
実際の採用候補は`candidate_details`内の`selected: true`を確認してください。
文章向けの一次候補はqpdfであり、グレー候補が採用されても一次候補列はqpdfの値を維持します。

字体統一の要求は`font_replacement_requested`、字体名とWindowsフォントファイルのSHA-256は
`replacement_font`・`replacement_font_sha256`で確認できます。qpdfが採用された場合や保護・dry-runでも
font_replace行には要求を残します。`text_extraction_changed`は字体置換候補採用時のMuPDF抽出差で、
コピー・検索時の空白や改行が変わった場合に`true`です。他の閲覧ソフトでの一致を保証する値ではありません。

再実行は入力・出力のSHA-256や設定ハッシュ等で再利用可否を判定します。現行の処理schemaは6で、
保護規則、全指定パターン、文章レシピ、採用条件もハッシュへ含みます。旧schemaの成功記録を
そのまま再利用せず、新しい保護方針で再評価します。DB移行は列追加で、旧行を削除しません。
字体統一ではWindowsフォントのSHA-256、固定レシピ、fontTools・pikepdfの版も再利用条件に含みます。
統合CLIはCSVを現在の入力・要求・出力と照合し、保護結果では原本とのSHA-256一致も必須にします。

## 6. dry-runと比較HTMLで確認する

`--dry-run`は保護判定と要求設定を記録します。保護予定は`DRY_RUN_PRESERVED`です。
圧縮候補・完成PDF・比較PDF・PNG・HTMLは作りません。状態DBやdry-runレポートは作成・更新する場合があり、
削減量・画質・本実行の成功を検証したことにはなりません。

`--pdf-preview`は文章・罫線表・文章スキャン・写真・字体統一・保護結果を対象に、原本と実際の完成出力を
同じ倍率で比べるローカルHTMLを作ります。通常処理が`ERROR`または`SKIPPED_*`のPDFは描画しません。
保護結果には理由を表示し、追加の圧縮候補は作りません。追加比較DPIは保護されていない写真PDFだけに適用します。
比較HTMLの100ページ上限は字体統一にも適用され、通常PDF処理の上限とは別です。

保存先は出力の親フォルダーの`pdf-preview/<runid>/index.html`です。原本・完成出力のコピーと
描画画像を含むため、閲覧・共有には実行フォルダー全体を使います。比較資料の失敗は通常の完成PDFを
変更せず、比較側のエラーとして終了コード1へ反映します。比較設定だけの変更は通常PDFの再処理を要求しません。

## 実装と検証記録への案内

処理を追う入口は、[config.py](../pdf-shrink/src/pdf_shrink/config.py)（指定と設定ハッシュ）、
[policy.py](../pdf-shrink/src/pdf_shrink/policy.py)（保護判定）、
[worker.py](../pdf-shrink/src/pdf_shrink/worker.py)（候補・採用・復旧）、
[text_optimize.py](../pdf-shrink/src/pdf_shrink/text_optimize.py)（文章候補と検証）です。
字体統一は[font_pipeline.py](../pdf-shrink/src/pdf_shrink/font_pipeline.py)（候補処理）、
[font_replace.py](../pdf-shrink/src/pdf_shrink/font_replace.py)（置換候補の生成）、
[font_validate.py](../pdf-shrink/src/pdf_shrink/font_validate.py)（独立検証）で追えます。
全モジュールの役割は[PDF README](../pdf-shrink/README.md#モジュール境界)にあります。

[2026-09-09の保護・文章向け検証記録](validation/2026-09-09-text-policy.md)には、合成文書、
実資料5冊の原本保護、許可した2冊の写真圧縮の結果があります。実資料の文章スキャンは未指定であり、
その削減率・可読性を検証済みとはしていません。描画一致や差分検査も、人間の可読性・OCR精度・
すべてのPDFビューアーでの同一表示を保証するものではありません。

[2026-09-10のWindowsフォント置換検証記録](validation/2026-09-10-windows-font-replacement.md)には、
游ゴシックを使った通常CLIでの101ページ1冊の圧縮、再実行・dry-run、表示と抽出の確認結果があります。
字体・太さとコピー／検索時の推定空白の変化も記録しています。
